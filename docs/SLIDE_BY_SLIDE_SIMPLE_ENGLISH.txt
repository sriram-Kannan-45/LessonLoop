Hello, my project is called LessonLoop. Its goal is to create lessons that
are accurate and easy for beginners to understand. A user enters a topic.
The system writes a lesson, checks it, and improves it when checks fail.
It approves the lesson only when every required check passes.

checks its own output before approving it for a learner.

PAGE 10 - WHY LANGGRAPH FITS THIS WORKFLOW
======================================================================
SAY THIS:
The next step depends on the result. A passing lesson can finish. A failed

also do this. I chose a graph because its separate steps and decisions
are easy to explain and test.

WHY I DID THIS:
The main requirement is a controlled loop with clear reasons for each route.

PAGE 11 - FIVE LANGGRAPH TERMS IN PLAIN WORDS
======================================================================
SAY THIS:
A node is one task, such as writing a lesson. An edge is the route to the
next task. State is the shared notebook containing the topic, lesson,
feedback, and retry count. Compile prepares the connected workflow to run.
Ainvoke starts the workflow asynchronously. Compile does not train a model
or approve a lesson.

WHY I DID THIS:
These concepts let each task receive the information it needs and pass
its result to the next task.

ACTION: Point to each term. Say ainvoke as "A invoke" if that is easier.

======================================================================
SAY THIS:

the draft. Validate_structure checks required fields and source mappings.
Evaluate_lesson checks the teaching quality. If a check fails and drafts

saves the final status. Unresolved failures after draft three are marked
NEEDS_REVIEW, rather than approved.

======================================================================

QUICK WORD MEANINGS FOR PRACTICE
======================================================================
Rubric: the checklist used to judge a lesson.
Grounding: giving the model reference material to support its answer.
Evaluation: checking the output against the rules.
Regeneration: writing a revised draft using failure feedback.
Persistence: saving records so they remain after a restart.
Fallback: trying a configured backup provider after an eligible failure.
Audit: a saved record that helps someone inspect what happened.
Calibration: testing whether the evaluator's decisions match reviewed examples.
Dependency: a package another package needs in order to work.
Fine-tuning: additional model training using example data.

Practice tip: understand the meaning first. You do not need to memorise
every sentence. Use your own simple words while keeping the facts accurate.
